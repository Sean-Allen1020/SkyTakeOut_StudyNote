### 自定义依赖的制作
- 以 `阿里云文件上传工具类` 为例子 (完整代码请浏览本目录内的`aliyun-oss-spring-boot`)


1. 创建 `aliyun-oss-spring-boot-starter` 模块
   - 在项目中创建新Module，以固定的命名规则命名
   - 删除除`pom.xml`以外的所有文件
   - 精简化`pom.xml`文件：
```xml
    <?xml version="1.0" encoding="UTF-8"?>
    <project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
            xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
        <modelVersion>4.0.0</modelVersion>
        <parent>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-parent</artifactId>
            <version>4.0.1</version>
            <relativePath/> <!-- lookup parent from repository -->
        </parent>
        <groupId>com.aliyun.oss</groupId>
        <artifactId>aliyun-oss-spring-boot-autoconfigure</artifactId>
        <version>0.0.1-SNAPSHOT</version>
        <name>aliyun-oss-spring-boot-autoconfigure</name>
        <description>aliyun-oss-spring-boot-autoconfigure</description>

        <properties>
            <java.version>21</java.version>
        </properties>

        <dependencies>
            <dependency>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-starter</artifactId>
            </dependency>

        </dependencies>
    </project>
```
--------------------------------------------------------------------------------------
2. 创建 `aliyun-oss-spring-boot-autoconfigure` 模块，在 `starter` 中引入该模块
   - 在项目中创建新Module，以固定的命名规则命名
   - 删除除`pom.xml`和`src文件夹`以外的所有文件
   - 精简化`pom.xml`文件，内容同上
   - 在`starter`的`pom.xml`中引入该配置模块的依赖：
```xml
    <dependency>
        <groupId>com.aliyun.oss</groupId>
        <artifactId>aliyun-oss-spring-boot-autoconfigure</artifactId>
        <version>0.0.1-SNAPSHOT</version>
    </dependency>
```
--------------------------------------------------------------------------------------
3. 在 `aliyun-oss-spring-boot-autoconfigure` 模块中实现自动配置功能，并在`resource包`中定义自动配置文件 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`

   - AliyunOss文件上传本身所需的 工具类，属性类，配置类
    - **工具类**：
    ```java
    public class AliyunOssOperator {

        private AliyunOssProperties aliyunOssProperties;

        public AliyunOssOperator(AliyunOssProperties aliyunOssProperties){
            this.aliyunOssProperties = aliyunOssProperties;
        }

        //...
    }
    ```
    > 由于没有`lombok依赖`，所以只能手动写`构造体`等方法
    ------------------------------------------------------

    - **属性类**：
    ```java
    @ConfigurationProperties(prefix = "aliyun.oss")
    public class AliyunOssProperties {

        private String endpoint;
        private String bucketName;
        private String region;

        // 手动写 setter/getter 方法
    }
    ```
    > 由于没有`lombok依赖`，所以只能手动写`构造体`等方法
    > 由于是第三方依赖，涉及到启动类扫包的问题，所以不能写`@Component`来将bean放到IOC容器管理，所以这里没有该注解
    ------------------------------------------------------

    - **配置类**：
    ```java
    @EnableConfigurationProperties(AliyunOssProperties.class)
    @AutoConfiguration
    public class AliyunOssAutoConfiguration {

        @Bean
        @ConditionalOnMissingBean
        public AliyunOssOperator aliyunOssOperator(AliyunOssProperties aliyunOssProperties) {

            return new AliyunOssOperator(aliyunOssProperties);
        }
    }
    ```
    > 配置类整体书写逻辑与包内配置类的实现逻辑几乎一样，区别仅在于类上的两个注解
    > 属性类由于少了`@Component`，`@ConfigurationProperties`本来会报错，此处的`@EnableConfigurationProperties`则弥补了这一点
    ------------------------------------------------------
