**不同的包中，IOC容器不是共享的**
**启动类默认只会扫描它所在的那个包的文件**
**<u>所以不同包中第三方依赖，即便写上`@Component`也不能在包外部进行`@AutoWired`</u>**

**解决方案1：**
- 在启动类中写上`@ComponentScan(basePackages = {"包名1","包名2",...})` 的注解

-------------------------------------------------------------------------------
**解决方案2：**
- 在启动类中写上`@Import(类.class, ...)` 的注解
- 通过`ImportSelector`：
  1. 创建`ImportSelector`的实现类
```java
    public class MyImportSelector implements ImportSelector {

        public String[] selectImports(AnnotationMetadata importingClassMetadata) {

            return new String[]{"com.example.xxx", "全类名", "..."}
        }
    }
 ```
  2. <u>在启动类写上`@Import(MyImportSelector.class)`</u>
   
> 该方案可以通过`ImportSelector` 来实现批量导入

-------------------------------------------------------------------------------
**解决方案3：**
- 将需要导入的依赖统合到一个注解里，即将 `@Import` 注解封装到一个注解里

```java
    @Retention(RetentionPolicy.RUTNTIME)
    @Target(ElementType.TYPE)
    @Import(MyImportSelector.class)     //根据解耦原则，依然建议先用 ImportSelector 进行批量封装
    public @interface EnableHeaderConfig{

    }
```
> 然后将注解`EnableHeaderConfig`写到启动类即可(注解名自定义，通常以`Enable`开头。这里仅作示范)

**方案3为常用方案，时长与方案2一起用**

-------------------------------------------------------------------------------
**解决方案4：**
- SpringBoot启动类中的`@SpringBootApplication`底层实际上已经实现了`ImportSelector + @Import + @EnableXxx` 的自动配置流程
- 此时，只需要在依赖的`配置类`中写上 `@AutoConfiguration`，即可让它变为`自动配置类`。
- 最后将自动配置类的全类名写在`META-INF/spring/ org.springframework.boot.autoconfigure.AutoConfiguration.imports`
```java
    @EnableConfigurationProperties(HeaderServiceProperties.class)   //如果需要配置属性，且属性类那边写了 @ConfigurationProperties(prefix = "...") 的话，配置类这边就要写这个注解
    @AutoConfiguration
    public class HeaderServiceAutoConfiguration {

        @Bean
        @ConditionalOnMissingBean
        public HeaderService headerService(HeaderServiceProperties headerServiceProperties) { 
            return new HeaderService();
        }
    }
```
> 并且可以通过在bean上加入`@ConditionalXxx`的注解，来让SpringBoot自动判定是否需要注入对应的bean
> 该方案是SpringBoot中最泛用的自动配置方式，方案123都有点古早了
> 文件 `4.自定义starter` 中，详细讲了根据 方案4 的自定义依赖的实现方法
